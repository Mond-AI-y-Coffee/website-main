## The core idea
In our own testing, every major model obeyed the attacker. So the model isn't the defense; what you put around the agent is: keeping it from leaking credentials, limiting the tools and data it can reach, and deciding what it can do without a person. A small team doesn't need a security team to get this right. It needs a short list of controls, set up before its agents can reach customer data or money.

---

## What's working / not working
- **Working:** We run agent fleets that operate entire divisions, with the governance, monitoring and assurance that keep them accountable as the models underneath them keep changing.
- **Not working (yet):**
  - There's no way to get advance notice when a lab changes a model. We catch it by watching behavior, after it happens.
  - Human approval doesn't scale. The more agents you run, the more the approval queue becomes the bottleneck.
