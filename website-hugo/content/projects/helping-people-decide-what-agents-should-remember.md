## What are you building?

Larine is an agentic harness for product and service owners, bringing definition, design, development, and testing into a collaborative team interface.

Product Memory is a design bet: agents should carry forward conventions about how a product should behave, including expectations that aren't evident in its code. We want to give users enough awareness to make rational, well-informed decisions about those memories.

## The core idea

The problem isn't just what an agent can remember. It's what a person needs to understand before deciding that a convention should guide future agent work: its source, scope, and likely consequences; conflicts with existing guidance; and why it belongs in memory rather than a product specification.

## What's working / not working

- **Working:** The implementation has explicit memory search and retrieval, provenance, and an age- and usage-based relevance review policy. Those mechanisms exist; they don't establish that a memory is correct or useful in context or over time.
- **Not established yet:** Memory is still a design bet, not a demonstrated success story. Whether people receive enough context to judge memories wisely remains something to test. We also need to test the UX for helping people decide when drift or changes mean memories need to be managed.

## Open questions

- What should people see to judge whether a proposed memory is a lasting convention, where it applies, what it could change, and whether a specification would be a better home—without overwhelming them?
- What should prompt someone to narrow, update, or retire a remembered convention, and how should Larine notice and make that need visible?
- Should a new memory be allowed to guide an agent before a person reviews it, or should informed human approval be required before it becomes active?

## If we only discuss one thing, it should be:

What must a person understand—and explicitly authorize—before a convention from one conversation guides future agent work?
